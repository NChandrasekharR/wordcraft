## Critical

### C1. Layout overflows the viewport once a source is added (repro X18)
`.app` (`css/styles.css:52`) is a grid with no row template, so the implicit
`auto` row grows to the sidebar's content height (~1,111px) as soon as the
Parameters panel appears (and on every reload with a saved canvas). On any
viewport shorter than ~1,110px:
- toasts (Undo, errors, **"Confirm clear"**) render at y≈1,083 → invisible, so Clear appears to do nothing;
- zoom controls (y≈1,087) and the compare panel (bottom 1,111) are off-screen;
- at ≤900px the Controlled Experiment and Sensitivity Map buttons are unreachable (`html, body { overflow: hidden }` blocks wheel/PageDown).

Playwright auto-scrolls before clicking, which is why earlier harnesses missed it.
**Fix (verified at 768/800/900/1080):** `.app { grid-template-rows: minmax(0, 1fr); }`.

## Medium

- **M1 Cost leaks (repro X09, X10).** Concurrency pools don't cancel siblings on the first failure (Sensitivity Map: error after 5 calls, 12 made) — `js/sensitivity.js:297`, `js/ablation.js:257`. Clear doesn't abort in-flight calls — `js/app.js:1513`.
- **M2 Key hygiene (repro X12).** A remembered key cannot be removed from the UI (empty Save is a silent no-op, `js/app.js:236`). All `nchandrasekharr.github.io/*` Pages sites share one origin, so any other page published there can read `anthropic_api_key`. No CSP, although every script is external (a strict `script-src 'self'` is nearly free).
- **M3 Suggestions (repro X13).** Closing Analysis clears the array but not the checkmarks → reopened items look selected, button enabled, click does nothing (`js/app.js:1044`). While any suggestion is selected, the main Generate button silently ignores the sliders (`js/app.js:1226`).
- **M4 Cards (repro X15, X16).** Card text can't be selected (`user-select: none`, `css/styles.css:756`); a resized card clips content with no scroll; auto-placement with fixed 300px rows overlaps long cards (`js/app.js:846`).
- **M5 Accessibility (repro X14, X17).** axe-core 4.13: 16 contrast failures (primary buttons 3.66:1 vs 4.5), 3 unlabelled sliders, 2–3 unnamed selects. Modals: no dialog role, no Esc, focus escapes. Card actions hover-only; canvas mouse-only.
- **M6 Performance.** Word LCS is O(n·m) time+memory on the main thread: 1,000 words ≈ 0.1s/33MB per pair, 3,000 words ≈ 1.3s/290MB. Full-pool Experiment = 36 diffs, Sensitivity Map ≈ 108 → multi-second freezes (`js/util.js:30-63`).
- **M7 Ablation mutates Swarm state (repro X06).** Reuses the agent panel and never restores its title — later Swarm runs are labelled "Ablation Lab" (`js/ablation.js:351`).
- **M8 API details.** Sonnet 5 priced $3/$15 in code, actual $2/$10 (`js/swarm.js:36`, `js/sensitivity.js:35`, `tests/ablation.test.js:154`) → estimates 50% high. Retries skip 408/504, ignore `retry-after`, no request timeout (`js/api.js:22`). No `pause_turn` / `refusal` handling. Verified correct: model IDs, `output_config.format`, web-search tool version split (`web_search_20250305` for Haiku 4.5, `_20260209` otherwise).
- **M9 Unverified risks (need a live key).** Full-pool Sensitivity judge batches 80 pairs in one call with `max_tokens: 1000` (~12.5 tokens/score) → likely truncation → silent fallback to wording-only (`js/measure.js:20`). Sonnet 5 runs adaptive thinking when `thinking` is omitted, which may consume small budgets (ablation judge 400, planner 1024).
- **M10 Slider quantization (product).** 201 slider positions → 7 distinct prompts; values in (−20, 20) produce contradictory instructions ("Tone: Neutral (more formal)") — `js/util.js:14-26`.

## Product read (where the build diverges from the thesis)

- **The default gesture is the anti-pattern.** Generate Variant is a blind single re-run; the control group is opt-in. The cached baseline pool makes pairing cheap — a "meaning moved X% · noise Y–Z%" chip on every generated card would make the thesis the default.
- **Knobs are quantized** (M10) — the control surface overstates its resolution.
- **Verdicts aren't calibrated as the copy claims** (H2–H4) — for a product whose promise is honest verdicts, these are product bugs, not math nits.
- **Provenance can lie** (H8) — the canvas's arrows are its memory.
- **The Swarm judge isn't blind** (L4).
- **Per-paragraph instrument, not yet a lab** — no fixtures / golden set, no promotion path (thesis §6).

## Engineering practices vs best in class

Solid: disciplined shared-global scope; consistent escaping (all XSS probes inert); strict structured-output schemas with graceful judge degradation; commit-on-success baseline pool; pure helpers unit-tested, including tests that enforce the honest voice.

Missing: CI (Pages deploys `main` directly); committed e2e suite (now `tests/e2e/`); lint/format/stylelint config; tests for the riskiest code (`api.js` retry + SSE parser, `experiment.js` `verdictFor` which has no Node export, persistence); visible failure signals; cross-module state isolation.
